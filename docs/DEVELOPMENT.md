# 开发顺序与断点续开发说明

## 当前检查点

- [x] 项目可以通过 `npm start` 启动。
- [x] 总览、任务、笔记、项目四个首批页面已建立。
- [x] 任务、笔记、项目有统一的本地数据结构，首次打开载入示例数据。
- [x] 新增任务、笔记、项目，以及标记任务完成、删除笔记，会写入浏览器 `localStorage`。
- [ ] 编辑和删除任务、编辑笔记及项目详情仍待开发。
- [ ] 尚无搜索、导入导出、账号或跨设备同步。

## 建议的开发顺序

1. **补齐任务管理**：编辑和删除、输入校验、到期状态和更顺手的筛选。
2. **补齐笔记管理**：编辑、搜索和按项目筛选。
3. **完善项目上下文**：项目详情页，集中查看并筛选关联的任务和笔记。
4. **保护本地数据**：导出和导入 JSON；需要改动存储格式时加入 `schemaVersion` 迁移。
5. **评估同步需求**：只有确定需要多设备或多人访问后，再选择后端、账号和部署方案。

每一步先确认用户实际需要的范围，再实现一个完整、可运行的小切片；保持无需构建工具即可启动，除非需求已证明需要引入框架或后端。

## 从断点继续

1. 先读本文件和仓库根目录的 `README.md`，确认当前检查点。
2. 阅读 `src/data.js` 了解 `schemaVersion`、数据字段和本地持久化；阅读 `src/app.js` 找到对应页面与事件。
3. 只实现当前顺序中的下一项，沿用现有页面结构、浏览器本地存储和原生 JavaScript。
4. 若数据字段需要变化，先明确旧数据的迁移方式，再更新 `schemaVersion`，不要直接覆盖用户已保存的数据。
5. 启动 `npm start`，检查受影响页面和交互，再更新本文件的检查点。

给 Codex 的续开发提示可以是：

> 请先阅读 README.md 和 docs/DEVELOPMENT.md，从“当前检查点”确认项目状态。沿用现有原生 JavaScript 和 localStorage 结构，完成开发顺序中的下一项；只修改本项必需内容，结束时更新检查点并检查启动方式。
